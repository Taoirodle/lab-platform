# L.A.B — V1.8 build plan

**Started:** 2026-09-28. **Mandate (Tao):** "start building to a proper V1.8". The platform leaves beta: app **1.8.0** everywhere, a release that holds up now that family use it from outside the house.
**Git:** commit + push each finished chunk to `main` (public repo: never secrets, no tailnet names or addresses beyond `100.x`); tag `app-v1.8.0` at release.

**What "proper" means here** (from three surveys of the code, 2026-09-28):
- The Hub left the house (Tailscale), but its family surface trusted anyone who reached it, and Tao's tailnet also holds work machines. Away from home it has to be family-only.
- The Admin USB key only locked the *page*; every admin API answered anyone on the home network.
- The app treats a refusal as "offline", ignores the address the wizard gives it, never learns the away address, and quietly swallows failed writes.
- Several things claim to work and don't (App Store apps with no backend, a load-shedding area nobody could set, a web Hub that drops generated widgets).

**Rules for every chunk** (same as the September run)
1. Implement → verify for real (server: deploy + `curl` + `scripts/smoke.sh` at home *and* over the tailnet; app: `npx tauri build`, launch the exe; UI: load it) → commit → push → tick + Log line.
2. No fake data. If something can't be real yet, the UI says so.
3. A finished vertical slice beats three half-done ones.
4. Deploy = `scp` to `/srv/lab/manager/…` then `sudo systemctl restart lab-manager`; bump the Manager `VERSION` when server code changes.
